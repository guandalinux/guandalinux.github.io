A private-network data platform on public cloud: Terraform, private endpoints and hybrid DNS

On an Azure data platform closed to the internet, I followed the Terraform work for pre-production and documented the private endpoints, service by service. I explained in 9 steps how a DNS query travels from the corporate network to the cloud's private zones.

Period
November 2023 to March 2024
My role
One contributor among several

One contributor among several, sole author of the documentation. The Terraform code was pushed under a team account and its merge requests were merged by a colleague, except one; the original DNS architecture predates my arrival.

Context

A data platform relied on Azure managed services: storage, orchestration, search, data warehouse and catalogue. Their endpoints had to be made private while staying reachable over VPN from the corporate network. Everything hinged on DNS resolution between that network and the cloud.

What I did

  1. I checked that the data orchestrator read storage through a managed private endpoint, then provisioned it with Terraform.
  2. I opened and followed the tickets for the pre-production Terraform modules: network, storage, orchestration, search, data warehouse.
  3. I identified a subscription limit on the data warehouse instances and had the flow needed for VPN access opened.
  4. I wrote 7 documentation pages in eight days, each with an architecture diagram, listing 15 endpoints to make private across 5 services.
  5. I configured and documented step by step the private-access setup of the data catalogue, covering everything Terraform cannot configure: permissions, integration runtime, managed private endpoints, storage connection and scanning.
  6. I added to the existing DNS documentation the 9-step path of a query, from corporate DNS to the cloud's private zones.
  7. I deployed in pre-production the application container that uses the storage and search services, wrote its playbook and deployment job, then handed that job to the project team.
