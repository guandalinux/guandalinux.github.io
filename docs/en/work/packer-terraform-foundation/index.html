From machine image to cluster: Packer templates and a Terraform foundation the team took over

I built the chain that produces virtual machine templates, then machines and Kubernetes clusters, with one variables file per target. The Terraform foundation has become a team effort: others now add servers and clusters to it.

Period
May 2025 to March 2026; additions until November 2026
My role
Initiator, later taken over by others

Initiator of both repositories, then one contributor among several. I wrote about 95% of the current template code, and 19 of the 79 non-merge commits in the Terraform repository, including the nine that laid the foundation.

Context

The Kubernetes clusters and virtual machines run on two VMware platforms: vSphere and a Cloud Director private cloud. I created the template repository in May 2025, then the Terraform repository on 8 January 2026. The goal: go from a machine image to a cluster connected to the secrets vault and to ArgoCD, all in code.

What I did

  1. I built the template repository around two parameterised Packer definitions, one for Kubernetes nodes and one for virtual machines.
  2. These two definitions produce 14 variants: two Debian versions, compute or storage Kubernetes nodes, and application, database or mixed machines.
  3. In January 2026 I replaced the encrypted secrets file that was committed to the repository with secrets read from a vault at build time.
  4. I made the templates exportable to OVF and ready for cloud-init, with volumes resized on first boot and hot-add of CPU and memory.
  5. From 8 January to 4 March 2026 I laid the Terraform foundation: modules for machines, clusters, vault integration and GitOps tool installation.
  6. I stored Terraform state on internal object storage, encrypted and locked, with one workspace per cluster or server.
  7. I wrote the repository's first Kubernetes cluster module: Cilium networking, a virtual IP for the control plane, etcd backups every 5 hours (5 kept), and upgrades one node at a time with worker nodes drained first.
  8. In October 2026 I fixed a failed template import into the private cloud by reworking the disk sizes.

Result

As of 18 November 2026, the Terraform repository declares 7 Kubernetes clusters, 3 of them built with my module, and 37 variables files (one per cluster, server or environment, plus a shared file).

What happened next

Eight days after my commit of 16 February 2026, a colleague added a second cluster module variant following the same layout: Makefile, state backend, one variables file per target. Since then, other team members have been adding servers and clusters, mostly through new variables files, and most commits now come from them.
